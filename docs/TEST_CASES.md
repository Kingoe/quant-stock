# 测试用例

本文档定义项目需要覆盖的测试范围。后续功能变化时，必须同步更新。

## 1. 测试原则

- 优先使用固定测试数据，保证测试结果可重复。
- 单元测试不能依赖实时行情。
- 外部数据源需要 mock，也就是用模拟数据替代真实网络请求。
- A 股交易规则必须单独测试。
- 财务数据的有效日期必须测试，避免未来函数。
- 策略测试要可解释，不使用看不懂的期望值。

## 2. 后端单元测试

### 配置模块

- 能读取默认策略配置。
- 持仓数量非法时应报错。
- 因子权重总和不等于 1 时应报错。
- 交易成本为负数时应报错。

### 存储模块

- 能创建必要的 SQLite 表。
- 能插入和更新股票基础信息。
- 能插入日行情，并避免重复数据。
- 能按股票和日期区间查询行情。
- 能查询最新可用数据日期。

### 数据源模块

- 能把外部数据源字段转换成内部字段。
- 能通过统一 `DataProvider` 接口屏蔽不同数据源差异。
- 本地 CSV 数据源能读取股票基础信息和日行情，并按股票、日期过滤。
- 本地 CSV 数据源缺少必需字段时必须显式报错。
- AkShare 数据源适配测试必须使用 mock，不访问真实网络。
- 可选字段缺失时不应崩溃。
- 必填字段缺失时应给出清晰错误。
- 一批数据校验失败时，不能写入部分脏数据。

## 3. 股票池测试

- 能剔除 ST 和 *ST 股票。
- 能按评分日期剔除上市不足一年的股票。
- 能剔除调仓日停牌股票。
- 能剔除低于成交额阈值的股票。
- 能剔除无效 PE 或 PB 的股票。
- 能保留满足条件的中证 800 成分股。
- 调试模式下能输出股票被剔除的原因。

## 4. 因子测试

### 估值因子

- 在 PE 为正且有效时，PE 越低估值得分越好。
- 在 PB 为正且有效时，PB 越低估值得分越好。
- 股息率越高估值得分越好。
- 无效或负 PE 应按配置剔除或标记不可用。

### 质量因子

- ROE 越高质量得分越好。
- 毛利率越高质量得分越好。
- 经营现金流 / 净利润越高质量得分越好。

### 成长因子

- 营收增速越高成长得分越好。
- 净利润增速越高成长得分越好。
- 成长数据缺失时不应导致整个评分流程崩溃。

### 动量因子

- 60 日和 120 日涨跌幅应基于复权价格计算。
- 价格历史不足的股票不能得到误导性的动量得分。

### 风险和流动性因子

- 波动率越低风险得分越好。
- 最大回撤越低风险得分越好。
- 近 20 日平均成交额越高，流动性得分越好。

### 打分流程

- 去极值能限制极端值影响。
- 分位数排名输出稳定范围内的分数。
- “越低越好”的因子能正确反向。
- 加权总分应符合配置权重。

### 因子有效性分析

- 未来收益应使用评分日之后的行情，不能使用评分日当天价格冒充未来价格。
- 未来收益优先使用复权收盘价，缺失时回退普通收盘价。
- IC 应只对齐同时有因子分数和未来收益的股票。
- Rank IC 应基于因子排名和未来收益排名计算。
- 样本不足、因子常数或收益常数时，相关系数应返回空值。
- 分层收益应按因子分数从高到低稳定分组，并计算每层平均未来收益。
- 持有天数和分层数量等参数非法时必须显式报错。

### 行业中性化

- 同一行业内应按原始分数转换为 0-1 相对分数。
- 同一行业内高分股票中性化后仍高于低分股票。
- 原始分数并列时应使用平均排名。
- 行业样本不足时应返回中性分，避免单只股票行业被过度放大。
- 缺失行业应统一归入“未知”行业。
- 最小行业样本数等参数非法时必须显式报错。

## 5. 组合测试

- 能选择排名前 N 的股票。
- 能应用单票最大仓位限制。
- 能应用行业最大仓位限制。
- 新进入目标组合的股票进入买入列表。
- 当前持仓但不在目标组合的股票进入卖出列表。
- 当前持仓且仍在目标组合的股票进入持有列表。
- 高分但未入选最终组合的股票进入观察列表。
- 涨停或停牌股票不能生成买入订单。
- 跌停或停牌导致无法卖出时，需要标记风险。

## 6. 回测测试

- 能根据交易日历生成周频调仓日。
- 第一版能使用下一个交易日开盘价作为成交价。
- 买入和卖出都应计入佣金。
- 只有卖出计入印花税。
- 成交价应计入滑点。
- 买卖数量应按 100 股整数手处理。
- 不能出现违反 T+1 的当天买入当天卖出。
- 涨停日不能买入。
- 跌停日不能卖出。
- 停牌持仓保持不变。
- 每笔交易后现金和持仓应正确变化。
- 组合净值计算正确。
- 能计算总收益、年化收益、最大回撤、夏普比率、胜率、换手率。
- 能与沪深 300、中证 500 基准序列对比。

## 7. 参数实验测试

- 能记录实验名称、说明、参数、指标、备注和创建时间。
- 参数和指标应以 JSON 保存，并在读取时还原为结构化数据。
- 能按实验 ID 查询单条实验记录。
- 能按创建时间倒序列出最近实验。
- 列表数量限制必须生效。
- 空实验名称必须显式报错。
- 参数或指标无法 JSON 序列化时必须显式报错。

## 8. API 测试

- `GET /api/overview` 返回总览指标。
- `GET /api/rebalance/latest` 返回买入、卖出、持有、观察列表。
- `GET /api/factors/scores` 支持分页和排序。
- `GET /api/factors/scores/{stock_code}` 返回股票详情；不存在时返回 404。
- `GET /api/backtest/summary` 返回核心回测指标。
- `GET /api/backtest/equity-curve` 返回按时间排序的净值曲线。
- `GET /api/backtest/drawdown` 返回按时间排序的回撤曲线。
- `GET /api/config/strategy` 返回当前策略配置。
- `GET /api/data/status` 返回最新数据日期和任务状态。

## 9. 前端测试

- 应能渲染整体导航。
- 总览页能展示核心指标和图表区域。
- 本周调仓页能展示买入、卖出、持有、观察列表。
- 因子评分页支持搜索、排序和空状态。
- 回测分析页能展示指标卡和图表。
- 策略配置页能展示当前配置。
- 数据状态页能突出过期或缺失数据。
- 接口加载中、空数据、错误状态都要有清晰提示。

## 10. 集成测试

- 能使用固定测试数据跑完整周频策略流程。
- 生成确定性的因子评分。
- 生成确定性的调仓建议。
- 生成确定性的回测指标。
- 前端能通过模拟 API 数据加载所有页面。

## 11. 人工验收

每个里程碑完成前，需要检查：

1. 后端单元测试通过。
2. 前端测试通过。
3. 后端能本地启动。
4. 前端能本地启动。
5. 打开页面后每个页面都有数据或清晰空状态。
6. 能导出最新调仓报告。
7. 任务规划和更新日志已经同步更新。

## 11. 报告、调度和模拟运行

- 每周 HTML 报告能生成可读的买入、卖出、持有、观察列表。
- Excel 和 CSV 导出包含股票代码、名称、动作、目标仓位、总分、排名、原因和风险提示。
- 本地定时任务能添加每日任务、每周任务，并能启动和关闭。
- 运行日志能记录 pending、running、success、failed 状态，并支持按任务类型查询。
- 手动运行本周策略接口能创建运行日志，成功时返回建议数量和 action 统计，失败时保留错误日志。
- 本周调仓页面能触发手动运行，并展示运行成功或失败状态。
- 模拟交易账本能创建、成交、取消订单，并正确更新现金、持仓、佣金和收益。
- 策略信号能记录建议、执行结果、待执行信号和执行摘要。
- 模拟组合绩效能计算总收益、最大回撤、夏普比率、日波动率、胜率。
- 模拟运行摘要接口能返回最新资产、现金、收益、回撤、波动率和信号执行摘要。
- 总览页能展示模拟运行区域；无数据时展示清晰空状态。
