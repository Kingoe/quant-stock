# 数据源计划

本文档定义第一版数据源选择、数据边界和预研重点。目标是在真正接入数据前，先明确哪些数据必须有、哪些数据不能依赖实时接口完成测试。

## 1. 第一版数据源

第一版采用“双入口”数据源：

- `LocalCsvProvider`：本地 CSV 数据源，用于稳定测试、回放和手工导入。
- `AkShareProvider`：AkShare 在线数据源，用于个人研究场景下补充免费数据。

业务逻辑只依赖统一 `DataProvider` 接口，不直接调用 AkShare。

原因：

- Python 生态中使用方便。
- 覆盖 A 股常见行情、指数、估值、财务数据。
- 适合个人项目快速验证。

约束：

- akshare 接口可能变化。
- 免费数据源稳定性和字段完整性需要验证。
- 单元测试不能直接依赖 akshare 实时返回。

## 2. 必需数据

### 股票基础信息

需要字段：

- 股票代码
- 股票名称
- 交易所
- 上市日期
- 行业
- ST 状态

用途：

- 股票池过滤
- 页面展示
- 行业约束

### 指数成分

第一版需要：

- 沪深 300
- 中证 500
- 中证 800

用途：

- 基础股票池
- 基准对比

### 日行情

需要字段：

- 交易日期
- 开盘价
- 最高价
- 最低价
- 收盘价
- 成交量
- 成交额
- 复权价或复权因子

用途：

- 动量因子
- 风险因子
- 流动性因子
- 回测成交

### 估值数据

需要字段：

- PE
- PB
- PS
- 股息率

用途：

- 估值因子
- 异常估值过滤

### 财务数据

需要字段：

- ROE
- 毛利率
- 营收增速
- 净利润增速
- 经营现金流
- 净利润
- 披露日期或可用日期

用途：

- 质量因子
- 成长因子
- 避免未来函数

### 交易状态

需要字段：

- 停牌状态
- 涨停价
- 跌停价
- 是否涨停
- 是否跌停

用途：

- 股票池过滤
- 回测交易限制
- 调仓风险提示

## 3. 测试数据原则

- 单元测试使用本地 fixture 数据。
- fixture 数据应覆盖正常、缺失、异常、停牌、涨跌停、ST 等场景。
- 不在单元测试中访问网络。
- 数据源接口测试可以单独标记为集成测试。

## 4. 数据源封装要求

外部数据源必须通过接口封装，业务逻辑不能直接调用 akshare。

推荐结构：

```text
backend/app/data/
  providers.py         # 统一 DataProvider、LocalCsvProvider、AkShareProvider
  *.py                 # 内部数据结构和数据库加载器
```

这样后续可以替换为 tushare、聚宽、米筐或付费数据源。

当前实现状态：

- `LocalCsvProvider` 已支持股票基础信息、交易日历、指数成分、日行情、估值和财务数据的 CSV 字段映射。
- `AkShareProvider` 已支持股票基础信息、日行情、交易日历、指数成分、估值和财务指标的基础映射。
- AkShare 单元测试使用 mock，不访问真实网络。
- AkShare 免费接口可能变化，字段缺失时会返回清晰错误，后续真实运行需要通过集成验证确认。
- AkShare 基础财务映射使用报告期作为披露日期的临时近似值；M12-5 数据质量检查需要继续标记披露日期质量风险。

CSV 文件约定：

- `stocks.csv`
- `trading_calendar.csv`
- `index_constituents.csv`
- `daily_prices.csv`
- `valuations.csv`
- `financial_metrics.csv`

## 5. 预研清单

进入数据底座任务前，需要确认：

- akshare 是否能稳定获取中证 800 成分股。
- akshare 是否能获取足够历史日行情。
- 日行情是否有可用复权信息。
- 估值数据字段是否完整。
- 财务数据是否包含披露日期。
- 停牌和涨跌停状态是否能可靠计算或获取。
- 指数行情能否用于基准对比。

## 6. 备用方案

如果 akshare 某类数据不可用：

- 指数成分：考虑 tushare、聚宽、米筐或本地手工导入。
- 财务披露日期：考虑更高质量数据源，或者第一版降低财务因子权重并明确限制。
- 停牌和涨跌停：可从日行情价格和涨跌停价推导，必要时先用保守规则。

任何数据源替换都必须更新本文档和 `docs/TECHNICAL_ARCHITECTURE.md`。
